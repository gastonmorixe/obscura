## 3. What the highest profile sets

Profile -> spec hop: `Chrome154 => ("chrome_154", v154::emulation)` maps to the
`v154` module in `src/emulate/profile/chrome.rs:1932-1962`, which calls
`standard_mod_generator!` (`src/emulate/macros.rs:191-224`) with four parts:

| part | location |
| --- | --- |
| TLS | `tls_options!(9, CURVES_3, sorted_trust_anchors())` chrome.rs:1934 |
| HTTP/2 | `http2_options!(3)` chrome.rs:1935 |
| headers | `header_initializer_with_zstd_priority` chrome.rs:1936 |
| per-OS sec-ch-ua + UA table | chrome.rs:1937-1961 |

TLS macro arm 9 at `src/emulate/profile/chrome/tls.rs:55-65`:
`permute_extensions`, `enable_ech_grease`, `pre_shared_key`, `CURVES_3`
(`X25519MLKEM768:X25519:P-256:P-384`, tls.rs:70), `NEW_SIGALGS_LIST`
(mldsa44/65/87 + RSA/ECDSA, tls.rs:103-116), `trust_anchors`,
`grease_sigalgs_enabled(true)`, `alps_use_new_codepoint(true)`.

Shared defaults live in `ChromeTlsConfig -> TlsOptions`
(`src/emulate/profile.rs:174-233`): cipher list `CIPHER_LIST` (tls.rs:72-89),
`grease_enabled(true)`, OCSP + SCT, TLS 1.2..1.3, ALPS `HTTP2`,
Brotli certificate compression (tls.rs:118). ALPN is left at the wreq default
`[HTTP2, HTTP1]` (`wreq src/tls.rs:595`), Chrome does not set it explicitly.

HTTP/2 `http2_options!(3)` (`src/emulate/profile/chrome/http2.rs:37-63`): window
6291456, conn window 15728640, max_header_list 262144, header table 65536,
stream dependency 0/255/exclusive, pseudo order m-a-s-p, fixed settings order,
`enable_push(false)`.

macOS awareness: yes for headers only. `Platform` is a 5-variant enum
(`src/emulate.rs:188-194`), the `v154` table has a `MacOS` row (chrome.rs:1939-1943)
with `"Chromium";v="154", "Google Chrome";v="154", "Not A(Brand";v="99"` and the
macOS UA. `platform_headers!` (`src/emulate/macros.rs:232-256`) matches the row and
also feeds `sec-ch-ua-platform` through `Platform::platform()` (`src/emulate.rs:196-211`).
TLS and H2 are **platform-independent**: one `tls_options!` and one `http2_options!`
per profile version, no `Platform` input. So MacOS changes `sec-ch-ua`,
`sec-ch-ua-platform` and UA only.

## 4. Does a profile switch need a matching btls rev

The `trust_anchors` / `grease_sigalgs_enabled` chain:

1. `ChromeTlsConfig.trust_anchors` / `.grease_sigalgs_enabled` ->
   `TlsOptions` fields (`wreq src/tls.rs:222, 257`; builder at
   `src/tls.rs:399-403, 478-484`). Present in pinned wreq `c6fd8b1a` (2026-10-10).
2. `src/tls/conn.rs:343-345` calls `set_requested_trust_anchors(ids)` and
   `conn.rs:399-401` calls `set_grease_sigalgs_enabled`, both btls FFI.
3. btls pinned `f5a8a483` (2026-10-09) exports both at
   `btls/src/ssl/mod.rs:2101-2103` and `:2247`.

Both setters also exist in wreq-util's own patch rev `12988758` (2026-09-10), so
wreq-util's patch and obscura's pin are compatible on this API. **No btls bump is
required** for Chrome155, because PR #126 reuses `tls_options!(9, CURVES_3,
sorted_trust_anchors())` verbatim. Chrome156 is different: PR #132 also sets
`options.server_padding = Some(0)`, and `server_padding` does not exist in pinned
wreq `c6fd8b1a` (grep count 0 in `src/tls.rs`). That field lands in wreq
`e035a872535274933b1574a3f8bfb946d98b24dc` (2026-10-29,
`feat(tls): expose optional server padding requests`), which PR #132 moves the
wreq-util patch to.

## Exact Cargo.toml change to reach a higher profile

Chrome155 (PR #126 head), smallest change. Only `crates/obscura-net/Cargo.toml:44`
plus the code line:

```toml
wreq-util = { git = "https://github.com/0x676e67/wreq-util", rev = "7a14bb6fba6c0156b80c3cf0f858f57098c07989", optional = true, features = ["emulation-compression"] }
```

and `crates/obscura-net/src/wreq_client.rs:232`:
`Profile::Chrome154` -> `Profile::Chrome155`. No wreq or btls bump.

Two cautions on Chrome155, both from the PR body/tests:
- The `v155` table has **only a Windows row** (chrome.rs diff, `[(Windows, ...)]`).
  Asking for `Platform::MacOS` falls through `platform_headers!`'s `_` arm to the
  Windows row, so you would emit a Windows UA and `sec-ch-ua-platform: "Windows"`
  while `stealth_navigator_platform` is still `MacIntel`
  (`wreq_client.rs:75`). That is an inconsistency. Either drop to Chrome154 (macOS
  row exists) or patch the profile with a macOS row.
- `STEALTH_USER_AGENT` (`wreq_client.rs:61-62`) and `STEALTH_SEC_CH_UA`
  (`:69`) hardcode 154. They must move in lockstep or the header override at
  `:400` contradicts the TLS profile.

Chrome156 (PR #132 head) additionally needs:

```toml
# workspace Cargo.toml [patch.crates-io]
wreq = { git = "https://github.com/0x676e67/wreq", rev = "e035a872535274933b1574a3f8bfb946d98b24dc" }
```

and `Profile::Chrome156`, with the same Windows-only table caveat.
